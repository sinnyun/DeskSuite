## 3. 图片与附件统一资源约束（已由用户确认）

### 3.1 数据所有权

1. 笔记、画板等业务插件只保存资源永久链接及必要的名称、类型、alt/caption 等元数据，不复制、上传、转码或保存图片和附件原始文件。
2. 本地原文件保持在用户原位置。通过现有 resources 注册/解析；不新增图片库、附件存储目录、独立注册表、协议或原始文件缓存。
3. 笔记正文的新图片引用使用现有永久 URI，例如 `![说明](desksuite-resource://local/<uuid>/content.png)`；普通附件使用 Markdown 链接。资源永久 URI 是持久化引用。
4. 显示前调用 resources.resolve 取得当前版本 URL。带 `?v=` 的 URL、blob/data URL、base64、解码像素和运行时租约不得写入正文、草稿、笔记历史或导出包。
5. 笔记自身的 Markdown 文本、YAML、恢复草稿和笔记版本仍可按既有链路保存；禁止保存的是被引用的图片和附件原始字节，不禁止保存笔记正文。

### 3.2 插入与显示

| 输入 | 处理方式 |
| --- | --- |
| 已注册资源 URI/ID | 复用 resources.resolve，持久化标准永久 URI |
| 本地文件路径 | resources.register(path)，只注册原文件，不复制 |
| 磁盘支持的 File 对象 | 复用 resources.registerFile；由现有 bridge 参数适配取得原路径 |
| 系统文件选择 | 复用 resources.choose 与注册流程，不自建上传流程 |
| 纯剪贴板图片、内存 File、截图像素 | 无本地源文件时明确提示不支持；不自动生成 PNG、不保存 blob、不回退为 base64；已有资源链接可按链接粘贴 |
| 旧 Markdown 相对路径 | 相对于笔记文件定位已有原文件，再通过统一资源注册/解析显示；不复制文件、不创建 assets；是否将正文改写为永久 URI须由显式迁移动作决定 |
| 外部来源链接（例如 Eagle） | 仅通过现有来源解析服务转换为统一资源引用；没有相应能力时提示不支持，不在笔记插件另建下载器 |

普通 img 显示使用统一协议 URL；不要求为 Milkdown 图片引入 Leafer 或使用画板的解码租约。若已有消费者适配可复用，应通过服务获取，禁止跨插件文件 import。可选服务不可用时提供能力缺失提示，不能静默换成另一套存储。

### 3.3 失联与生命周期

- 原文件缺失、无权限、资源被撤销、不可解码时，显示名称、失联/不可用状态、重试与可用的定位入口；保留永久引用。
- 原文件变化后重新 resolve，使用服务给出的新版本 URL，不实现笔记专用版本缓存。
- 当前 resources 契约尚未提供通用重新关联能力；如需补齐，应在统一资源提供方扩展并经服务调用，不能声称已有自动重关联。
- 从笔记删除引用、归档笔记或清空笔记回收区，不删除原文件，也不自动全局 forget：同一资源可能由画板或其他笔记共享。
- 笔记导出只包含正文、属性和资源链接/必要清单，不打包图片或附件字节；换机后不能保证本机资源 URI 可用，不宣称自包含便携包。

### 3.4 与现有画板对齐

[canvas-ops-resources 契约](../src/renderer/src/plugins/canvas-ops-resources/PORTS.md) 已明确：文件路径/File 注册原件，场景只保存永久 URI 与资源类型，不复制或转码；异步插入捕获目标会话并支持取消。笔记沿用这些语义，不相互 import。

该契约另有 pasteImage 路径会经 canvasInput 生成剪贴板 PNG 源文件。这条现有行为不属于本次笔记方案可复用的范围；不能因“画板已有”而默认沿用。本文不修改画板，跨域行为统一如需调整应另行确认范围。

## 6. 实施与验收完成定义

- 主进程能力属于 Cordis 插件；跨插件协作只用服务注入。渲染层通过 SDK 服务与 bridge；不改 preload 增加第二桥，不让业务界面进入 workbench。
- 资源输入只调用现有 resources 服务。需要补共享能力时扩展资源提供方，禁止笔记内部另做资源存储或协议。
- 笔记内容采用 700ms 防抖自动保存；目录授权后沿用文件操作计划、打开基线比较和执行指纹检查，草稿恢复仍与原文件保存分开。筛选、排序、标签页和面板状态不触发写盘。新增/变更接口同步 PORTS.md 与 PORTS_ZH.md。
- 验证脚本全部放 scripts/verify/ 并复用 common.mjs，在 VERIFY.md 登记；产物放 artifacts/verify/。隔离实例显式 --access full，可写根限定 artifacts/verify/samples。
- 每个开发阶段通过 guard、typecheck、构建后，必须启动应用，经自身 MCP 执行功能操作、只读 DOM/几何断言、capture_window 截图并查看。不可用 DOM click/dispatch、鼠标键盘或系统对话框自动化绕过 MCP 缺口。
- 专项必须覆盖重复选择、外部冲突、新建竞态、并发/超时、草稿重启、失效目录、序列化与资源链接往返。资源项检查源文件哈希/路径不变，笔记及其持久化数据中无附件字节，资源可与画板共用，删除笔记不撤销其他消费者的资源。
- 2026-10-30 实现后执行 `guard`、`typecheck`、`build`、隔离 full-access launch、`notes-editor.mjs`、`note_query` 搜索/大纲、MCP smoke、路径选择 MCP、`errors.mjs` 和 `capture_window` 截图；专项目标检查通过，渲染错误/警告为 0。截图与报告在 `artifacts/verify/`。
