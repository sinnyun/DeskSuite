# canvas-provider-scene

- Snapshot.textEditing:string|null and setTextEditing(id|null) track transient native input ownership; the UI displays editing rather than saved while the official editor is open. This field is not scene data.

- Scene v1 now optionally includes groups:{id,parent?,x?,y?,rotation?,scaleX?,scaleY?,skewX?,skewY?}[]; both group transforms and node geometry are board-space, with native Group reparenting handled by the engine. Node skewX/skewY are optional. Legacy absent group records synthesize identity containers. Validation rejects cyclic/missing group ancestors, depth >64, colliding IDs and singular group scales.
- edit structurally shares equal node records, nodes arrays, groups/guides/bookmarks/view; prunes empty group records and retains live ancestors. select(ids,expandGroups=true) supports hierarchical expansion; native selection uses false so entering a group can select one leaf. Equal selections do not emit. flush invokes optional commitEditing before draining persistence, ensuring native text is committed before navigation/close.

- Metadata: canvas / provider / scene; entry `index.tsx`; core renderer plugin, no UI contribution.
- Provides SDK renderer service `canvas`. No plugin file imports. IPC dependency: `whiteboard` list/summaries/get/set/remove/complete and whiteboard:flush events. No MCP registrations, configuration or browser persistence of its own.
- `getSnapshot()` returns stable `{id,scene,selection,revision,saving,error,boards,canUndo,canRedo,interaction,cropEditing}`; `subscribe(fn)` returns unsubscribe. Consumers must treat snapshots as read-only. Scene/BoardNode structural contracts are mirrored locally in consumers' `contract.ts`; authoritative persistence validation is in main storage `scene.ts`.
- Lifecycle/navigation: `open(id?)`, `create(title?)`, `remove()`, `refresh()`, `replace(json)`, `flush()`. Navigation is serialized; IDs and scenes change together. Replacement validates before acceptance. Automatic saves use 500ms trailing debounce and 2s maximum wait. Pending immutable snapshots serialize only at write time; acknowledged identical JSON skips IPC. saving includes waiting/writing; errors take precedence in UI. Explicit flush cancels timers and drains the serial writer, including in-flight edits. Switching/closing/deleting awaits writes. Failures remain pending for retry. Store supplies atomic backup/recovery. refresh uses whiteboard.summaries in one call. History snapshot sizes are weakly cached, avoiding repeated serialization of the entire stack. Equal views skip updates.
- Plugin setup listens to whiteboard:flush and acknowledges via whiteboard.complete only after persistence (application-close barrier).
- `edit(fn)` clones, validates and commits one undo transaction; redo is cleared; undo bounded to 100 entries and approximately 16 MiB JSON characters (the latest snapshot is retained). `history('undo'|'redo')`. History is session-only; view movement saves without adding history entries.
- `select(ids)` expands logical groups and frame members. `setView({x,y,zoom})` bounds zoom to .05–8; `setInteraction(boolean)`; `setCropEditing(id|null)` records which image is being cropped (transient, clears interaction mode); `report(error)`.
- Extension commands: `register(name,handler)` returns disposal; duplicate names throw. `command(name,args?)` invokes a handler, reports missing optional plugins as capability errors. Handlers must use `edit`, not mutate snapshots.
- Inline content extension: `registerContent(kind,ReactComponent)` returns disposal; `getContent(kind)`. Component props `{node,interactive}`. Keys match `node.resourceKind` (pdf/markdown/text/etc.) or node.type. Rendering extensions get resource URLs through the independent resources service; no file imports from providers. Missing extensions fall back to Leafer file cards. Interactive DOM overlays are active only in content mode. Static export of future custom DOM viewers requires an explicit canvas representation.
- Never calls global Leafer Resource.destroy or owns original files.
- Optional source integrations: registerInspector(id,Component<{node}>) / getInspectors() add/remove property components and notify subscribers. registerResourceEnricher(id,reference=>Promise<{name?,tags?}|undefined>) / enrichResource(reference) initialize ordinary node fields, without provider-specific scene data. registerLinkResolver(id,url=>Promise<stableURI|undefined>) / resolveLink(url) handle optional external schemes; unknown schemes fail, never downloaded. All registries reject duplicate IDs and return lifecycle disposal. Resource metadata persistence remains in its owning main plugin, keyed by the node's unified URI.
