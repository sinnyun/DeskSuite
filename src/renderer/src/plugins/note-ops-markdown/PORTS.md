# PORTS — note-ops-markdown (renderer)

- Domain / class / name: `note` / `ops` / `markdown`
- Entry: `index.tsx`
- Editing is delegated to the `noteEditor` renderer service published by `note-provider-editor` (Milkdown Crepe, WYSIWYG, Markdown as source of truth). When that plugin is disabled the panel degrades to a plain textarea instead of crashing.
- Slot contributions: `sidebar.activity` opens the `notes` panel; `floating.panels` provides a theme-aware, three-column notes workspace with collapsible navigation and document inspector sidebars around the editor. The inspector contains outline, backlinks, tags, attributes, and version history; editor formatting uses the note editor's floating selection toolbar.
- Consumes the required `ui` service, optional renderer `resources` service, and main IPC services `filesystem` (`listDir`, `listMore`, `readText`), `fileOps` (`plan`, `approve`, `execute`, `writeText`), `notePanel` (preferences, text-only draft operations), `eagleLinks.link` for Eagle originals, and `versions` (`list`, `create`, `restore`) for Lore history.
- Document changes are debounced for 700 ms and then written through the planned file operation API. The selected notes directory is already explicitly authorized; autosave still checks the opened baseline and the file operation fingerprint before execution. Unchanged serialized Markdown does not create a write plan or update file timestamps. Archiving a clean note asks for confirmation and moves it into `.trash/` through approved `mkdir` and `move` plans.
- Editor relies on `filesystem.readText` limits: text over 2 MiB or 200,000 characters is not editable, and truncated files are refused so unread content cannot be overwritten.
- Recursively reads Markdown files below the selected notes directory, up to depth 6 and 5,000 files; `.trash`, `assets`, and dot-directories are skipped unless the user enables trash browsing. It supports title/path filtering, full-text search, name/modified sorting, directory filtering, recent notes and subdirectory creation. Incoming backlinks come from up to 500 notes of at most 128 KiB each and ignore fenced and inline code.
- YAML frontmatter is split off before the body reaches the editor and re-attached verbatim when composing the save payload. The attributes editor updates title, tags, category, status and date with the YAML document model, preserving unknown keys and comments; malformed YAML blocks attribute changes with an explicit error. Tag aggregation scans only notes up to 128 KiB and the first 1,000 eligible notes, reports truncation, and filters from frontmatter tags only.
- The editor is remounted (via a `path#revision` key) whenever a note is loaded, created, or archived, because the engine reads its initial Markdown once on mount.
- The editor handle (read/replace Markdown) comes from the `onReady` callback of the `noteEditor` service and backs the MCP `setbody` / `inspect` actions; the textarea fallback exposes the same handle. `replaceMarkdown` also reports the new serialization back through `onChange`, because the engine's debounced `markdownUpdated` does not reliably fire for a whole-document replacement.
- The notes directory and the open note are remembered through the main-side `notePanel` service (`loadPreferences` / `rememberPreferences`, store key `note-panel-preferences`) and restored on startup, including after a renderer reload. A directory that no longer exists surfaces an error inside the panel; the panel never opens a system directory dialog by itself.
- Creating a note uses an inline title field in the sidebar (Electron has no `window.prompt`); its initial Markdown and later edits use the same debounced autosave path.
- Consumes the `note:action` broadcast from the main-side `note-ops-panel` plugin. Mutating `note_panel` actions include `setroot`, `open`, exact-path/unique-title `select`, `reload`, `new`, `setbody`, `setattrs`, `sourceMode`, `readingMode`, `findReplace`, `archive`, `restoreTrash`, `createVersion`, and `restoreVersion`; they answer through `notePanel.complete`. `note_query` provides read-only `search`, `outline`, `inspect`, and Lore `versions` listing. Document changes autosave; dirty-state checks and in-product confirmations remain active for destructive file and Lore operations.
- Image paste/drop registers only disk-backed files with the optional `resources` service and saves a permanent `desksuite-resource://` URI. The resource chooser inserts image and attachment links without copying bytes. Existing relative image paths are resolved against the note directory, checked to remain within the notes root, then registered/resolved for display without rewriting Markdown. If `resources` is unavailable, these operations report the missing capability.
- Eagle image IDs can be entered as `eagle://item/<ID>` and resolved through the existing `eagleLinks` IPC; the resulting permanent resource URI is inserted without copying or downloading source bytes. Other external schemes fail with an explicit error.
- Dirty text is debounced into the main `notePanel` draft store as text only for crash recovery and is separately autosaved to the source file. New-note writes pass `noOverwrite: true`; existing-note saves compare the on-disk baseline and require an explicit overwrite choice after a detected external change. The file operation plan still performs its own stale fingerprint check.
- The panel exposes source/WYSIWYG switching, find/replace, heading outline and text statistics. UI export produces Markdown or escaped HTML with resource links as links; it never embeds resource bytes. MCP-facing semantic actions include path-aware select, reload, body replacement, inspect, search and outline through `note_panel` / `note_query`; there is no manual save action.
- Recent notes are shown as tabs; switching first completes the outgoing note's autosave, and reopening restores any recovery draft. Reading mode makes the editor read-only without changing autosave behavior.
- Lore history uses the existing `versions` IPC service directly: it lists available revisions, creates a manual snapshot after the note is saved, and restores a selected revision after confirmation. Lore receives only the Markdown note file, which contains text and permanent resource URIs. The current Lore IPC exposes revision metadata but no text diff, so the panel does not render content comparisons.
- The main `note-ops-panel` owns the MCP tools; this renderer plugin registers no MCP tools or settings. Recent paths are persisted by the main `notePanel` preference Store, not browser storage.

- Directory selection uses `notePanel.pickDirectory` to grant writes via the native dialog; MCP setroot never grants access. Autosave snapshots live editor Markdown, subscribes before execution, and patches only the saved file's list metadata after completion without rescanning or reloading the editor. IME composition Enter does not create a note.
