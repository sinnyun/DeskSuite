# canvas-ops-resources

- Metadata: canvas / ops / resources; entry index.tsx; optional renderer plugin, no slots/config/events/MCP registrations. Consumes SDK services canvas/resources and IPC canvasInput.clipboardImage. Missing services fail with a capability error; disposal unregisters commands.
- Commands: import({paths?:string[],files?:File[],references?:string[],reference?:string,x?:number,y?:number}) -> node IDs. No source means native resources.choose; an explicit empty source list never opens a dialog. Paths/File objects register originals; references resolve existing identities. Maximum 100 explicit inputs, deduplicated by stable URI within each batch. Images acquire/release a decoded-size lease for proportional initial sizing (max 480x360, no upscaling); video becomes an inline player card; every other format becomes a file card. Stable URI + resourceKind are saved, not runtime URLs/bytes. Files are not copied or transcoded. Coordinates/view and destination board are captured before asynchronous work; navigation/plugin disposal cancels pending insertion. Unavailable/undecodable sources fail the whole scene insertion, without partial nodes.
- pasteImage() -> node IDs: main input plugin makes immutable clipboard PNG source, then normal import path.
- Insertions are a single canvas edit transaction. Renderer service contracts are structural and private to the consumer.
- import also accepts links?:string[] resolved through canvas.resolveLink into unified references. Every registered input runs canvas.enrichResource before node creation, merging only ordinary name/tags. Optional source plugins own recognition, metadata persistence and inspector UI. A failing source resolver/enricher prevents partial node insertion.
