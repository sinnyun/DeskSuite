# data-provider-eagle-links

- Metadata: data / provider / eagle-links; entry index.ts; object Cordis plugin. Injects resources/store/ipc/mcp; provides eagleLinks (declaration merged Context). No listeners, file copies, thumbnails, browser storage, or Eagle mutations.
- Reference: FileAtlas fileatlas-plugin-eagle-links in F:/AI/geren/pho_cordis. Queries fixed loopback Eagle API http://127.0.0.1:41595: V2 item/get and folder/get, V1 item/thumbnail. Each request times out at 5s, limits JSON to 4MiB, rejects redirects. Eagle must be running and expose V2 (4.0 Build21+). No API token is read, stored or logged.
- Original matching: validate alphanumeric item ID; reject absent/deleted/ambiguous items; require thumbnail parent <id>.info. noThumbnail uses returned file itself; otherwise require exactly one regular sibling matching extension and byte size, excluding thumbnail. Confirm dragged image is that canonical original; never silently substitute a thumbnail. The sibling layout is Eagle's observed convention, not a guaranteed public original-file API.
- Unified resources owns original registration/resolution. Versioned Store eagle-source-links v1 holds metadata snapshots keyed by stable resourceUri: itemId/name/originalPath/thumbnailPath/apiUrl/folders/tags/annotation/url/width/height/size/rating/updatedAt. No media bytes; whole-document JSON is limited to 256 MiB and 50k entries, with serialized writes and startup schema validation via Store. References remain local to this application/profile; never export private metadata into scene bytes.
- IPC and injected service eagleLinks: link({itemId? OR location?}) -> EagleSource; get(reference) -> cached EagleSource|null (works without running Eagle); inspect(reference,refresh=false) -> source|null, auto-recognizes .info originals and persists metadata, ordinary files return null; open(itemId) -> {itemId,deepLink}, shell.openExternal with validated fixed eagle://item/{id}. A dispatch success is not proof the external app selected the item.
- MCP: eagle_link({itemId?,location?}), eagle_source({reference,refresh?}), eagle_open_item({itemId}); registered through existing mcp and permission/audit policy. No arbitrary shell commands, API base overrides or content writes. IPC broadcasts eagleLinks:changed {reference} after a metadata snapshot write; config: none.
- Failures: API unavailable, trashed/missing item, wrong source or ambiguous siblings report descriptive errors. Eagle API envelope `message` is limited to 2,000 characters; provider-service errors use the shared main-process formatter and are bounded to 2,000 characters with credentials and local paths scrubbed before being thrown to consumers. Cache get is a snapshot; explicit refresh validates against current Eagle library and original path. A revoked/missing unified registration is governed by resources. No automatic polling/watching/deletion of metadata.

## Storage registration

- Injects `storage` and registers this plugin's data locations during `apply`; the Settings → Storage page aggregates their paths and on-disk sizes.
